# 🛠️ Portfolio – Developer Guide

A quick reference for working on this project. Written for someone new to Laravel and Vite.

---

## 📦 Tech Stack

| Layer       | Technology               | Purpose                                |
| ----------- | ------------------------ | -------------------------------------- |
| Backend     | **Laravel 11** (PHP 8.3) | Routing, controllers, data             |
| Frontend    | **Vue 3**                | UI components                          |
| Bridge      | **Inertia.js**           | Connects Laravel ↔ Vue (no API needed) |
| Styling     | **Tailwind CSS**         | Utility-first CSS                      |
| Build tool  | **Vite**                 | Bundles JS/CSS for the browser         |
| Server      | **Nginx**                | Serves the app                         |
| Runtime     | **PHP-FPM**              | Runs PHP                               |
| Database    | **MySQL 5.7**            | Data storage                           |
| Environment | **Docker**               | Runs everything locally                |

---

## 🚀 Starting the Project

```bash
# Start all containers (app, nginx, mysql)
docker compose up -d

# Check they are running
docker compose ps
```

The site will be available at **http://localhost:8080**

---

## 🔄 Daily Development Workflow

### When you change PHP/Laravel files (controllers, routes, etc.)

No action needed — changes are reflected immediately because the source folder is mounted into the container.

### When you change Vue/CSS files (`.vue`, `.css`, `.js`)

You need to **rebuild the frontend assets**:

```bash
# Option 1: One-time production build (recommended for testing)
docker compose exec app npm run build

# Option 2: Watch mode — auto-rebuilds on every file save (for active development)
docker compose exec app npm run dev
```

> ⚠️ **Important:** If you skip the build step after editing Vue files, the browser will still show the old version. Always rebuild after frontend changes.

## 🔗 How Inertia.js Works (the key concept)

Inertia is the "glue" between Laravel and Vue. Here's the flow:

```
Browser request → Nginx → PHP-FPM → Laravel Router → Controller
                                                          ↓
                                              Inertia::render('Home', $data)
                                                          ↓
                                              Sends JSON to Vue
                                                          ↓
                                              Vue renders Pages/Home.vue
```

- **No separate API** — Laravel controllers return `Inertia::render()` instead of JSON or Blade views.
- **Page components** live in `resources/js/Pages/` — each file maps to a route.
- **Data** is passed from the controller as the second argument to `Inertia::render()` and received as `props` in the Vue component.

**Example:**

```php
// PHP Controller
return Inertia::render('About', [
    'bio' => 'Full Stack Developer...',
]);
```

```vue
<!-- resources/js/Pages/About.vue -->
<script setup>
defineProps({ bio: String });
</script>
<template>
    <p>{{ bio }}</p>
</template>
```

## 🗺️ Routes & Pages

| URL                | Controller Method           | Vue Page                   |
| ------------------ | --------------------------- | -------------------------- |
| `/`                | `PageController@home`       | `Pages/Home.vue`           |
| `/about`           | `PageController@about`      | `Pages/About.vue`          |
| `/experience`      | `PageController@experience` | `Pages/Experience.vue`     |
| `/projects`        | `ProjectController@index`   | `Pages/Projects/Index.vue` |
| `/projects/{slug}` | `ProjectController@show`    | `Pages/Projects/Show.vue`  |

To add a new page:

1. Add a route in `routes/web.php`
2. Add a method in a controller (or create a new one)
3. Create the Vue file in `resources/js/Pages/`
4. Run `npm run build`

## ✏️ Adding/Editing Content

### Personal info (name, bio, skills, experience)

Edit the data arrays directly in the controllers — they have `// TODO` comments:

- `app/Http/Controllers/PageController.php` → `about()` and `experience()` methods
- `app/Http/Controllers/ProjectController.php` → `getAllProjects()` method

### Adding a project

Open `ProjectController.php` and add a new array entry inside `getAllProjects()`:

```php
[
    'slug' => 'my-new-project',       // URL: /projects/my-new-project
    'title' => 'My New Project',
    'shortDescription' => '...',
    'fullDescription' => '...',
    'technologies' => ['Laravel', 'Vue'],
    'github' => 'https://github.com/...',
    'live' => 'https://...',
    'featured' => true,
    'year' => '2026'
],
```

## 🐛 Troubleshooting

### 500 error on page load

```bash
# Check the Laravel error log
docker compose exec app tail -n 50 /var/www/storage/logs/laravel.log
```

### Page shows white / components not rendering

The Vite build is probably outdated. Rebuild:

```bash
docker compose exec app npm run build
```

### PHP package missing (e.g. "Class X not found")

```bash
docker compose exec app composer install
```

### Clear all Laravel caches

```bash
docker compose exec app php artisan optimize:clear
```

### Get a shell inside the container

```bash
docker compose exec app bash
```

## 🔑 Useful Commands

```bash
# Start containers
docker compose up -d

# Stop containers
docker compose down

# Rebuild frontend (after editing Vue/CSS files)
docker compose exec app npm run build

# Watch mode (auto-rebuild on save)
docker compose exec app npm run dev

# Clear Laravel caches
docker compose exec app php artisan optimize:clear

# View Laravel logs
docker compose exec app tail -f /var/www/storage/logs/laravel.log

# Open a shell in the app container
docker compose exec app bash

# Install new PHP package
docker compose exec app composer require vendor/package

# Install new JS package
docker compose exec app npm install package-name
```
